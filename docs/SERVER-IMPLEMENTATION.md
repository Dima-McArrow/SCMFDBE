## 2. Ключевые решения

**Старт с нуля, а не продолжение прототипа Codex.** Прототип был WPF-приложением на .NET Framework 4.x без SDK и NuGet (раздел 15). Раздел 41.3 это ограничение снял и требует Kestrel/WSS, TLS, bounded-очереди. Из прототипа взяты только проверенные знания: форматы строк Game.log и правило привязки корабля к EntityId. Код не копировался.

**.NET 10 (LTS), C#, без лишних зависимостей.** Внешние пакеты: только `QRCoder` (генерация QR) и `Microsoft.Extensions.*`. Тестовые: xUnit, `Microsoft.Extensions.TimeProvider.Testing`. Версии закреплены централизованно (`Directory.Packages.props`), у каждого проекта есть `packages.lock.json`.

**Линтеры — ошибки сборки.** `AnalysisLevel=latest-recommended`, `EnforceCodeStyleInBuild`, `TreatWarningsAsErrors`, `.editorconfig` с явными severity для IDE0005/IDE1006. `dotnet format --verify-no-changes` чистый.

**Логика отделена от Windows.** `Csmfd.Core` не знает о Win32: ввод, фокус, клавиатура, время — интерфейсы. Поэтому вся логика ввода, транспорта и журнала проверяется детерминированно на фейках (`FakeTimeProvider`, fake input sink), без реальных нажатий.

## 4. Протокол v2 (`Csmfd.Protocol`)

**Входящие (`ClientMessageParser`).** `hello`, `pair`, `ping`, `key`, `chat`, `releaseAll`.
- Отклоняются: дубликаты полей, глубина > 8, > 16 КиБ, комментарии, висячие запятые, одиночные суррогаты, управляющие символы в именах.
- Отсутствующее обязательное поле никогда не равно `null`; неизвестные поля игнорируются.
- Классы ответа на ошибку:
  - нет валидного `id` команды → `error malformed`;
  - `id` валиден, но содержимое плохое → `ack rejected` с `invalid` / `unknown_action` / `unknown_key`;
  - `v ≠ 2` → `unsupported_version` + close 4002;
  - неизвестный `type` → `unknown_type`.
- `KeyCommand` несёт уже найденный `ActionSpec`, а не сырые строки: дальше по коду нажать что-то вне allowlist физически нельзя.

**Allowlist (41.10).** 19 действий, каждое закреплено тестом построчно. Тап — `down`/`up`; удержание — `hold` (50…10 000 мс) и `up` для отмены. Модификаторы должны совпадать точно. Словарь из 68 клавиш (40.7).

**Исходящие (`ServerMessageWriter`).** Ручной `Utf8JsonWriter`, потому что delta различает «ключа нет» и `"ship": null`. Инварианты проверяются при сериализации (нарушение = исключение = баг сервера):
- `reason` в ack только у `rejected`;
- `commandId` + `reason` только у `input_cancelled` / `auto_released`;
- unknown QT — без имён и всегда `stale`; destination требует имя;
- пустые строки вместо `null` запрещены;
- `seq` / `revision` в 0…2^53−1.

Время всегда ISO 8601 UTC **с миллисекундами** (`2026-10-26T15:56:52.708Z`).

**Фикстуры** `tests/Csmfd.Tests/Fixtures/Protocol/*.json` — примеры из 41.7–41.10 (по одной на тип сообщения). Подходят как эталон для iPad-декодера.

## 5. Транспорт и безопасность

### 5.1. Listener (`WssHost`)
- Kestrel только на **выбранном пользователем** частном IPv4 (10/8, 172.16/12, 192.168/16) активного интерфейса. VPN-подобные адаптеры помечаются и никогда не выбираются автоматически.
- TLS 1.2/1.3, HTTP/1.1, compression выключена, handshake 10 с.
- Единственный endpoint `/csmfd`; запросы с `Origin`, query-строкой или не-WebSocket → отказ.
- Не больше 3 upgraded-соединений (1 controller + 2 неаутентифицированных).
- Адрес пропал или сменилась сеть → listener останавливается, ввод отпускается; адрес вернулся → listener снова поднимается.

### 5.2. Сессия (`ConnectionSession`)
- Один receive-loop и один send-loop; receive никогда не ждёт ввода, журнала или сети.
- Лимиты 41.6: 16 КиБ на сообщение по всем фрагментам (1009), binary (1003), невалидный UTF-8 (1007), сборка сообщения 5 с, hello 5 с, heartbeat 15 с (4004), > 100 сообщений/с (4005), > 20 протокольных ошибок (4005).
- Исходящие: control-очередь до 64 кадров (переполнение → release + 4005), дедлайн отправки 2 с (медленный клиент → release + 4005). Ack и error идут раньше state, state сливается в один кадр с debounce 20 мс; ClearDriver и переходы контекста идут без debounce.
- Закрытие: сначала отпускается ввод, затем close-фрейм, затем сессия **дочитывает** входящие до ответного close (до 2 с) и только после этого освобождает сокет. Без этого TCP RST уничтожал ещё не прочитанное клиентом сообщение (баг пойман тестами).

### 5.3. Pairing и доверие (41.5)
- Окно сопряжения открывается только локально (tray), длится 120 с; код — 6 цифр из CSPRNG, одноразовый.
- 5 неудачных попыток **суммарно** на окно, после этого окно закрывается.
- Токен — 32 случайных байта (base64url, 43 символа). На диске хранится только SHA-256; сравнение constant-time по всем записям без раннего выхода.
- Сертификат: ECDSA P-256 + SHA-256, EKU serverAuth, DNS SAN, срок 820 дней (правила Apple для TLS-сертификатов). Создаётся один раз и хранится как PKCS#12 под DPAPI (CurrentUser). Fingerprint — SHA-256 DER-сертификата (64 hex).
- Замена клиента: ввод старого соединения отпускается **до** активации нового, старое закрывается с 4001. Revoke закрывает соединение с 4006.
- Несопряжённый клиент не получает state, пути, имя игрока и любые данные журнала.

### 5.4. mDNS
`_csmfd._tcp` через `DnsServiceRegister` только на выбранном интерфейсе; TXT `v=2`, `tls=1`, `id=<serverId>`, `name=<displayName>`. Только для удобства: fingerprint из mDNS не берётся, ручной IP работает всегда. Память request и instance при deregister намеренно не освобождается (Windows может читать её до callback), это несколько сотен байт на перезапуск listener.

## 6. Ввод (`InputExecutor`, 41.11–41.12)

- **Один жест за раз.** Новый `down`/`hold`/`chat` при активном жесте → `busy`. `up`, `releaseAll` и аварийная отмена проходят всегда.
- **Проверки перед каждым новым жестом:** возраст команды ≤ 250 мс (`expired`), пауза, блокировка, фокус и процесс игры, физически зажатые модификаторы или та же клавиша (`busy`; защищает, например, от превращения N в Alt+N).
- **Тап.** Минимум 60 мс без блокировки потока: ранний `up` откладывается таймером, ack на него уходит после фактического отпускания. Без `up` тап отпускается через 10 с (`auto_released`).
- **Hold.** Дедлайн по monotonic-таймеру. `up` отменяет сразу. Таймеры защищены токеном: старый callback не может отпустить новый hold.
- **Аварийное отпускание** (минимум 60 мс игнорируется): потеря фокуса, выход игры, ClearDriver, новый контекст, пауза, обрыв, замена клиента, revoke, watchdog, выключение.
- **SendInput вставил не всё** → нажатое отпускается, `input_failed`, автоповтора нет. Не удалось отпустить → ввод блокируется до локального «Re-enable input» в tray.
- **Чат.** Последовательность на таймерах: клавиша чата → 120 мс → Unicode-текст → 30 мс → Enter. Фокус проверяется перед каждым этапом; Enter никогда не уходит в другое окно. Текст сверяется с allowlist эмоций (`emotes.txt`).
- **Дедуп и лимит** (`CommandGate`, на соединение): последние 200 id не исполняются повторно; новые жесты — 30/с с burst 30; `up`/`releaseAll` не лимитируются.
- **Deadlock-safety.** Executor вызывает выходные callback'и под своим lock; процессор журнала никогда не вызывает executor, удерживая собственный lock.

## 7. Win32-слой

- **`Win32InputSink`:** `SendInput` со скан-кодами Set 1 (`KEYEVENTF_SCANCODE`, `EXTENDEDKEY` для E0, правый Alt отдельно), мышь через `MOUSEINPUT` (`mouse1`–`mouse5`), чат через `KEYEVENTF_UNICODE`. Возвращает число вставленных событий.
- **`Win32PhysicalKeyboard`:** `GetAsyncKeyState` только для клавиш нового жеста; модификаторы проверяются без учёта стороны (зажатый правый Ctrl тоже конфликт). Глобального опроса клавиатуры нет.
- **`Win32GameWindow`:** путь образа процесса активного окна сравнивается с настроенным `StarCitizen.exe`. Если античит запрещает даже ограниченный запрос, есть запасной вариант по имени процесса (пишется в лог). Найденный процесс кэшируется и проверяется через `HasExited`; полное перечисление процессов — не чаще раза в 30 с.
- **`GameMonitor`:** смена активного окна через WinEvent-hook (без опроса), проверка присутствия игры раз в 2 с, пока она запущена, и раз в 10 с иначе; `game.build` из `build_manifest.id` (`RequestedP4ChangeNum`).
- **P/Invoke:** `LibraryImport` (source-generated), blittable-структуры; размер `INPUT` проверен тестом (40 байт на x64).

## 8. Game.log (41.13–41.14)

**`LogTailer`:**
- При старте позиционируется в конец файла: старые входы в канал и ATC не воспроизводятся как живые.
- Читает только добавленные байты, порциями (до 4 МиБ за проход; при отставании статус `catchingUp`).
- Строки режутся по байтам, поэтому у каждой строки точный offset, а разорванные UTF-8-последовательности и CRLF собираются корректно. Строка длиннее 64 КиБ пропускается и считается.
- Файл открывается так, что никогда не мешает игре писать, переименовывать и удалять его.
- Идентичность файла: время создания + побайтовый префикс (первая строка журнала содержит время старта). Префикс — главная защита: из-за file tunneling Windows пересозданный файл может унаследовать старое время создания.
- Замена, укорочение или потеря файла → новое поколение (`log.generation`), сброс контекста и ввода. Уведомление о сбросе приходит **до** первой строки нового поколения.

**`GameLogParser`.** Сначала дешёвая проверка маркера, затем source-generated regex с таймаутом. Распознаётся:
- вход в корабельный канал (`Added notification "You have joined channel '<Brand Ship> : <owner>'"`, только для известных производителей);
- спавн (`SetVehicleSpawningInformations`);
- навигационные строки с моделью и EntityId (`[QuantumTravel]`);
- выбор цели QT (`Player Selected Quantum Target - Local … selected point X as their destination`);
- локальный `ClearDriver`;
- `Hangar Request Completed`;
- конец сессии (`SystemQuit`, удалённый disconnect из `SC_Default`).

«Эхо»-строки уведомлений (без `Added notification`) не считаются повторным событием. Форматы взяты из реальных строк сборки 12913470.

**`GameLogProcessor`:**

| Событие | Поведение |
|---|---|
| Вход в корабельный канал | Новый `contextId`, `revision++`, ship `assumed`, ввод отпускается |
| Спавн + навигационная строка | Привязка модели и EntityId **без** новой revision (одна кандидатура, тот же владелец, ±10 мин) |
| Выбор QT для привязанного корабля | `destination`, `confirmed`, `internalName` (displayName пока `null`) |
| ClearDriver нашего корабля | `ship = null`, `noShip/clearDriver`, `revision++`, `contextId` и префикс производителя сохраняются, ввод отпускается |
| Повторный ClearDriver после ручного override | Снова `revision++` (по сохранённому EntityId завершённого контекста) |
| ClearDriver чужого корабля | Игнорируется |
| `requestLanding` реально отправлен | ATC `pending` с watermark = текущая длина файла, дедлайн 120 с |
| `Hangar Request Completed` после watermark в том же контексте | `answered`; более ранние записи не засчитываются |
| SystemQuit / выход процесса | Один переход `gameEnded` |

## 9. Приложение и UI

- **Один процесс** в сессии пользователя, обычные права, один экземпляр (mutex). Без Windows Service, без UAC, без глобальных хуков клавиатуры.
- **Tray:** статус · Pair iPad · Network · Trusted devices (revoke одного или всех) · Pause input · Re-enable input (только после сбоя отпускания) · Copy firewall command · Open data folder · Quit.
- **Окно сопряжения:** адрес, Server ID, fingerprint группами по 4 символа, крупный одноразовый код с обратным отсчётом, QR. Payload QR без секретов: `csmfd://pair?v=2&host=<ip>&port=47823&id=<serverId>&fp=<64 hex>`.
- **Необработанные исключения UI** пишутся в лог и показываются уведомлением; модального диалога .NET, который незаметно вешает tray, нет.
- **Иконка:** `Assets/csmfd.svg` (исходник) → `Assets/csmfd.ico` (кадры 16–256 px, растеризованы через Chromium). Иконка exe (`ApplicationIcon`); tray и окна берут кадр под текущий масштаб экрана.

**Данные** (`%LocalAppData%\CSMFD`; переменная `CSMFD_DATA_DIR` перенаправляет их для dev-прогонов):

| Файл | Содержимое |
|---|---|
| `config.json` | `bindAddress`, `gameExePath`, `gameLogPath`, `chatKey`, `displayName`, `serverId` (camelCase, читается без учёта регистра) |
| `server-certificate.bin` | Сертификат и ключ под DPAPI |
| `trusted-devices.json` | id, имя, время сопряжения, SHA-256 токена |
| `emotes.txt` | Allowlist эмоций (пока `wave`, `dance`, `gasp`) |
| `logs\csmfd*.log` | 3 × 1 МиБ; жизненный цикл и предупреждения; без токенов, кодов, ключей, содержимого Game.log и путей (категории `Microsoft.*` с уровня Warning) |

## 10. Тесты

Всего **253**, все зелёные. Покрытие по областям:
- **Протокол:** все фикстуры, негативные кейсы парсера, границы глубины и размера с обеих сторон, инварианты writer, allowlist построчно.
- **Executor** (на `FakeTimeProvider`): порядок модификаторов, отложенный `up`, дедлайны hold, устаревший таймер, `busy`, фокус, физические конфликты, `expired`, пауза, аварийное отпускание, потолок 10 с, частичный `SendInput`, блокировка и сброс, все этапы чата.
- **Pairing:** одноразовость кода, общий лимит ошибок, истечение окна, revoke, перезапуск.
- **End-to-end WSS на loopback** с настоящим TLS и pinning: неверный сертификат, `Origin`, несопряжённый клиент, неверный токен, неверный и верный код, ack, дедуп, фокус, замена клиента, revoke, 1009, 1003, state delta, heartbeat 4004 с отпусканием ввода.
- **Win32 (без реального ввода):** полнота и скан-коды таблицы клавиш, размер `INPUT`, чтение build, кадры иконки.
- **Game.log:** парсер на обезличенной фикстуре из реальных строк, tailer на временных файлах (EOF, offset, split UTF-8, truncate, замена с тем же именем, отсутствующий файл, длинная строка, порционное чтение, watermark), процессор по сценариям 41.18.

Сетевые тесты прогонялись три раза подряд для поиска гонок.

## 11. Проверка на ПК и замеры

Release-сборка, изолированный каталог данных, LAN `192.168.1.67`, клиент `csmfd-probe`, игра **не запущена**.

| Проверка | Результат |
|---|---|
| Неверный pin | Соединение отклонено на уровне TLS |
| Несопряжённый hello | `pair_unavailable` |
| Сопряжённый клиент | welcome + полный state (журнал `ready`, игра не запущена) |
| Ping RTT | 1,6–2,9 мс |
| Команда без игры | `rejected / game_not_running`, ничего не нажато; `up` → `ignored` |
| CPU в простое после прогрева | **0,052%** одного ядра (бюджет < 0,5%) |
| CPU первые 2 минуты | ~0,8%: одноразовый прогрев tiered JIT .NET |
| Память | 23–27 МиБ private bytes (бюджет < 100), стабильно |
| Всплеск журнала: реальный архив 117 МиБ | ~1,3 с CPU на весь сервер, разобран до конца, 16 переходов контекста, без ошибок |
| Выход через Quit | Штатный: listener остановлен, сервер завершён |

**Баги, найденные только на реальном ПК и исправленные:**
1. **Адаптер без IPv4.** `GetIPv4Properties()` бросал 10043 вместо `null`, и приложение висело на модальном диалоге .NET.
2. **`.gitignore` из шаблона.** Правила `Win32/` и `*.log` скрывали весь Win32-код и log-фикстуру; исправлено точечными исключениями, проверено чистым клоном.
3. **Ключи конфига.** Не совпадали с документацией (PascalCase вместо camelCase).
4. **Логи хостинга.** Писали полный путь к приложению.
5. **Перечисление процессов.** Выполнялось при каждой смене активного окна (заменено кэшем процесса).

## 13. Известные ограничения

- **Управление кораблём только предполагается** по входу в канал; подтверждённого состояния кресла нет. «Сел обратно без новой записи» → ручное включение Deck на iPad.
- **QT:** `freeMode` не отправляется (нет проверенной строки); `displayName` пока всегда `null`.
- **ATC:** в журнале нет requestId; поздний ответ на первый запрос может засчитаться второму.
- **Фокус и ввод:** проверка фокуса и `SendInput` не атомарны.
- **Аварийное завершение:** при kill процесса watchdog не отпустит клавиши; штатный выход отпускает всегда.
- **Античит:** если он не даёт прочитать путь процесса игры, используется проверка по имени.
- **Self-destruct** защищён только слайдером iPad; серверной двухфазной защиты нет.
- **Не проверено в игре:** работа `SendInput` под EasyAntiCheat, ввод текста в чат, переключение клавиши чата, длительности удержаний, F8, влияние на frametime, 2-часовой soak.
- **Малые размеры иконки:** в 16 px силуэт тонкий, на светлом таскбаре контраст слабее.
